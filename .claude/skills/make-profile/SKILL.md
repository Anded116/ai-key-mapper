# Профиль под игру

Профиль — `profiles/<exe без .exe>.toml`. Он наследует ядро стандарта `profiles/_base.toml`
(`extends = "_base"`) и переопределяет только то, что отличается в игре. Стандарт и приёмы —
`docs/layout-standard.md`, читать до начала. Образец готового профиля — `profiles/testrange.toml`.

## 1. Что узнать об игре

| Что | Где искать |
|---|---|
| exe игры | Steam: `steamapps/common/<игра>/`; у Unreal-игр настоящий exe в `.../Binaries/Win64/*-Win64-Shipping.exe`. Это значение `exe`, по нему профиль подхватывается сам |
| Клавиши действий | 1) конфиг игры: Unreal — `%LOCALAPPDATA%/<Игра>/Saved/Config/Windows*/Input.ini`; Unity — реестр `HKCU\Software\<Студия>\<Игра>`; Source — `cfg/config.cfg` (`bind`); id Tech / Build — `*.cfg` рядом с exe или в `Documents/My Games`; 2) PCGamingWiki, раздел Input — там же есть ли поддержка геймпада и можно ли смешивать его с мышью; 3) вики игры; 4) спросить пользователя |
| Оружие | сколько клавиш выбора оружия (цифры). 8 и больше — `slots = 8`, до 4 или оружие на крестовине (консольный порт) — `slots = 4` |
| Геймпад вместе с мышью | PCGamingWiki «Controller support» / «Simultaneous input»; Steam-страница; спросить пользователя, мигают ли подсказки |
| Античит | EAC, BattlEye, Vanguard, Ricochet — `SendInput` могут игнорировать или наказывать. Предупредить пользователя до сборки профиля (игры: Valorant, Fortnite, Apex, Rainbow Six Siege, PUBG, CoD, Battlefield 2042, Destiny 2 и т. п.) |
| Язык подсказок | как игра пишет клавиши: «нажми Ы» (русская раскладка) — по умолчанию из стандарта; если латиницей («Press S») — `prompts = "en"` в корне профиля. Окно рисует на кнопках крупно ту букву, которую покажет игра; переключатель РУ/EN в углу схемы пишет то же поле |

Не угадывать клавиши: чего нет в конфиге и вики — спросить одним списком.

Имена клавиш — `crates/engine/src/keys.rs` (регистр не важен): `Space`, `LShift`, `LCtrl`, `LAlt`,
`Esc`, `Enter`, `Tab`, `F1`–`F12`, `MouseLeft`/`MouseRight`/`MouseMiddle`/`MouseBack`/`MouseForward`,
`WheelUp`/`WheelDown`, стрелки `Up`/`Down`/`Left`/`Right`, `Minus`, `Equals`, `LeftBracket`,
`Semicolon`, `Quote`, `Comma`, `Period`, `Slash`, `Backquote`, `CapsLock`. Цифровой клавиатуры нет.

## 2. Раскладка

Ядро (раздел 1 стандарта) уже в `_base.toml`: L1 прыжок, R1 огонь, L2 прицел, L3 спринт одним кликом, R3 удар,
✕ использовать, □ перезарядка, △ граната, ○ присед, Options пауза, Create статистика, R2 — слой
оружия, R2 + Create/Options — сохранение/загрузка, R2 + L3 — гибрид ↔ WASD. В профиле игры
переопределить только клавиши, которые в игре другие, и заполнить свободные места:

- крестовина — предметы игры (аптечка, фонарик, метка); `mic` — редкая функция;
- тачпад — сетка 2×2: `pad_up_left`, `pad_up_right`, `pad_down_left`, `pad_down_right` (клик по
  четверти); `pad_left` / `pad_right` — половины целиком, четверть с привязкой перекрывает свою
  половину. **Пока на тачпаде есть свободные четверти, второй слой крестовины (`[layer.r2]`
  `dpad_*`) не занимать**: сетку тачпада пользователь запоминает легче, чем R2 + крестовину;
- `options = { tap = "Esc", hold = "M", hold_ms = 500 }` — тап/удержание, когда функций больше, чем
  кнопок. На кнопках меню (Options, Create, тачпад) всегда `hold_ms = 500`: обычное спокойное нажатие
  длится дольше стандартных 150 мс, и без этого вместо тапа срабатывает удержание (в Sons of the
  Forest Start из-за этого «не открывал меню»);
- `{ press = "F", double = "Z" }` — двойное нажатие для редкого действия;
- присед только переключением в игре, а хочется держать — оставить как есть и сказать
  пользователю: удержание поверх переключателя движок пока не умеет.

Поля привязки: `press` (держится, пока держишь кнопку), `tap` + `hold` (по времени
`timing.hold_ms`), `double` (второе нажатие в окне `timing.double_ms`), `next` (второе оружие пары,
`press` обязателен), `latch` (клик держит клавишу, пока левый стик отклонён, — бег, как на консоли;
в `_base` так стоит L3), `hold_ms` (свой порог удержания для этой привязки). Значение — имя клавиши
или список клавиш, нажимаемых вместе. Слой:
`[layer.<кнопка>]`, кнопка слоя может иметь и свою клавишу.

Кнопки: `l1 r1 l2 r2 l3 r3 cross circle square triangle dpad_up dpad_down dpad_left dpad_right
create options ps touchpad mic touch pad_left pad_right`.

### Оружие

```toml
[weapons]
slots = 8                       # □ 1/2, ✕ 3/4, ○ 5/6, △ 7/8: повторное нажатие — чётный слот
keys = ["1", "2", "3", "4", "5", "6", "7", "8"]
```

При 4 слотах — `slots = 4`, `keys` по одному на □ ✕ ○ △. Если оружие игры не на цифрах или
порядок другой — перечислить клавиши в порядке □ ✕ ○ △ (для 8 — парами).

### Движение: гибрид или WASD

- **Гибрид** (`mode = "hybrid"`) — игра сама читает левый стик, движение аналоговое. Подходит, если
  игра принимает геймпад и мышь одновременно и подсказки не мигают. По Bluetooth гибрид работает
  только в играх на SDL или Steam Input (DirectInput-игры перестают видеть стики после перевода
  DualSense в расширенный режим) — для остальных USB или WASD.
- **WASD** (`mode = "wasd"`) — стик шлёт клавиши. Для игр без поддержки геймпада или с мигающими
  подсказками. `walk = "LAlt"` — клавиша шага на неполном отклонении, если в игре есть шаг;
  `sprint = "LShift"` — спринт на полном отклонении, если спринт в игре удержанием (тогда L3
  освобождается). Другие клавиши движения — `keys = ["E", "S", "D", "F"]` (вперёд, влево, назад, вправо).
- **`[controller] hide = true`** — вместе с WASD, когда игра видит геймпад и из-за этого мигает
  подсказками или двоит ввод: движок прячет DualSense через HidHide, пока стик в WASD. Игру
  запускать после aikm. Для игр, которые геймпад не видят вовсе, не нужно.
- Steam Input для игры выключить (свойства игры в Steam → Контроллер), иначе ввод двоится.

### Калибровка

`real_world` — отсчётов мыши на градус при чувствительности игры 1; `in_game_sens` — текущая
чувствительность мыши в настройках игры. Движок шлёт `real_world / in_game_sens` отсчётов на
градус: от этого зависят и flick stick, и скорость гироскопа (в меню тоже — курсор меню идёт в
тех же отсчётах).

1. GyroWiki (gyrowiki.jibbsmart.com → Games) — таблица REAL_WORLD_CALIBRATION по играм.
2. По движку: Source и большинство шутеров с `m_yaw 0.022` — `45.4545`; Quake/id Tech — `45.4545`;
   Overwatch — `0.0066°` → `151.515`; Unreal — зависит от игры, искать в GyroWiki.

Только когда `real_world` взят из этих источников, спросить чувствительность мыши в игре и
записать её в `in_game_sens`: значение имеет смысл лишь в той шкале, в которой мерили `real_world`.

Если значения нет нигде — **не угадывать `real_world` и не делить догадку на чувствительность из
конфига игры**: шкалы у игр разные, ошибка получается кратной (Sons of the Forest: догадка 40 при
чувствительности 0.151 дала 265 отсчётов на градус — многократно быстрее нужного, курсор в меню
улетал). Вместо этого `in_game_sens = 1` и `real_world = 10` — заведомо медленно, затем замер:
флик стиком на 360° должен развернуть камеру ровно на круг. Пользователь говорит, на какой угол
повернулась камера (например, «на четверть круга» = 90°), новое значение
`real_world × 360 / угол`. Повторить, пока круг не сойдётся. Недокрут считать легко, перекрут на
несколько оборотов — нет, поэтому начинать снизу. Комментарий у `real_world` — «подобрано поворотом».

Замер удобнее делать кнопкой в окне: «Поворот камеры → Проверить поворот на 360°». Движок через
секунду после переключения в игру поворачивает камеру ровно на 360° по текущей калибровке,
пользователь отвечает, насколько она повернулась, и окно само пишет новый `real_world` в профиль.
Попросить пользователя сделать это в игре вместо ручного флика.

## 3. Шаблон

```toml
extends = "_base"
game = "Dusk"
exe = "dusk.exe"

[calibration]
real_world = 2.8649
in_game_sens = 0.1

[movement]
mode = "wasd"
walk = "LShift"

[buttons]
triangle = "T"                  # смена режима оружия
dpad_up = "F"                   # фонарик

[weapons]
slots = 8
keys = ["1", "2", "3", "4", "5", "6", "7", "8"]
```

Комментарий у привязки — что делает действие в игре, по-русски и коротко (2–4 слова): окно
показывает его подсказкой у метки кнопки на схеме, а метка — клавишу так, как её пишет игра на
русской раскладке (S → Ы).

## 4. Проверка

```bash
target/release/aikm.exe check profiles/<игра>.toml
```

Печатает игру, калибровку, режим движения и все привязки с учётом `_base`. Ошибка — исправить и
повторить. Затем скилл `verify-profile`. Пользователю коротко: что куда легло, что спросить в игре
(калибровка флика, мигают ли подсказки), что не перенеслось.
