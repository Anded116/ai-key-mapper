# Архитектура ai-key-mapper

Приложение-наследник JoyShockMapper: свой движок на Rust, интерфейс на Tauri, раскладку под игру собирает ИИ-агент из миничата. Решения по стеку приняты 2026-10-18.

## Компоненты

| Путь | Что это | Состояние |
|---|---|---|
| `crates/dualsense` | Ввод и вывод PlayStation-геймпадов по HID: USB и Bluetooth, кнопки, стики, курки, тачпад, гироскоп и акселерометр с заводской калибровкой, световая полоса; утилита `aikm-probe` (`Probe.cmd`) | этап 1 готов |
| `crates/engine` | Движок маппинга: биндинги, слои, гироскоп, flick stick, вывод клавиатуры и мыши | этап 2 |
| `crates/hidhide`, `crates/hidhide-cli` | Скрытие геймпада от игры через драйвер HidHide (IOCTL), журнал и сторож для отката | прототип готов, см. [hid-hiding.md](hid-hiding.md) |
| `app/` | Tauri: окно и трей, миничат с агентом, живая схема DualSense, профили, автозагрузка по игре | этап 3 |
| `.claude/skills/` | Скиллы агента: собрать профиль, откалибровать, проверить в TestRange, импорт JSM | этап 4 |
| `demo/` | TestRange — тестовая игра для отладки раскладок | есть |
| `jsm/` | Пресет JSM для TestRange: эталон поведения, пока свой движок не готов | есть |

## Поток данных

```
DualSense ──HID──▶ dualsense::Pad ──State──▶ engine ──SendInput──▶ игра
                        ▲   │                   │
           световая     │   └── калибровка IMU  ├──▶ app: живая схема (60 Гц)
           полоса ◀─────┘                       └──◀ app: профиль (горячая замена)
                                                         ▲
                                         агент ── пишет профиль ── проверяет в TestRange
```

Движок крутится в отдельном потоке с собственным циклом опроса (~1000 Гц для гироскопа, без привязки к кадрам UI). UI получает снимок состояния через события Tauri и ничего не рассчитывает сам.

## Профиль

Профиль — TOML-файл на игру в `profiles/<exe>.toml`. Агент пишет его, движок валидирует и подгружает на лету. Ядро стандарта ([layout-standard.md](layout-standard.md)) лежит в `profiles/_base.toml`, игровой профиль его наследует и переопределяет только переменные.

```toml
extends = "_base"
game = "TestRange"
exe = "testrange.exe"

[calibration]
real_world = 45.4545      # отсчётов мыши на градус при чувствительности 1
in_game_sens = 1.0

[movement]
mode = "hybrid"           # hybrid | wasd
walk_ring = "LAlt"        # клавиша шага при неполном отклонении (wasd)

[weapons]
slots = 8                 # 4 | 8; R2 + □ ✕ ○ △, второе нажатие — чётный слот
keys = ["1", "2", "3", "4", "5", "6", "7", "8"]
double_press_ms = 250

[buttons]
cross = "E"
square = "R"
triangle = "G"
circle = "LCtrl"
r3 = "V"
dpad_up = "F"
dpad_down = "MouseMiddle"
options = { tap = "Esc", hold = "M" }
create = { tap = "I", hold = "Tab" }
mic = "F8"

[layer.r2]
create = "F5"
options = "F9"
```

Импорт `.txt` JoyShockMapper переводит старые пресеты в этот формат: их понимает и агент, и человек.

## Движок (этап 2)

- **Кнопки:** нажатие, tap/hold, двойное нажатие, одновременное нажатие, диагонали; слои с удержанием (R2), внутри слоя работает двойное нажатие. Это главное, чего не умеет JSM.
- **Стики:** WASD с кольцами (шаг на неполном отклонении, спринт на полном), flick stick (флик, затем поворот, сглаживание малых поворотов как в JSM), классический aim.
- **Гироскоп:** калибровка в покое (непрерывная плюс по кнопке), кривая чувствительности min/max по скорости, выключение касанием тачпада, `PLAYER_TURN`.
- **Вывод:** `SendInput` — мышь относительными движениями с накоплением дробной части, клавиши по скан-кодам (для игр на DirectInput).
- **Состояние на экране:** какой слой активен, какое оружие даст следующее нажатие. Это видно в UI и на световой полосе.

## Контракт движок → UI (событие `state`, ~60 Гц)

```json
{
  "pad": { "model": "DualSense", "bus": "bluetooth", "battery": 0.8 },
  "buttons": ["L1", "R2"],
  "sticks": { "left": [0.1, 0.8], "right": [0.0, 0.0] },
  "triggers": { "l2": 0.0, "r2": 1.0 },
  "gyro_dps": [0.4, -12.0, 0.1],
  "touch": [{ "x": 0.3, "y": 0.6 }],
  "layer": "r2",
  "outputs": ["W", "LShift"],
  "profile": "testrange",
  "weapons": { "current": 5, "next_double": "circle" }
}
```

Команды UI → движок: `load_profile(path)`, `list_profiles()`, `calibrate_gyro()`, `set_hidden(bool)` (HidHide), `pause(bool)`.

## Агент (этап 4)

Как в ainimator: приложение запускает `claude -p <задача> --output-format stream-json --verbose` в корне репозитория, показывает поток событий в миничате, правки продолжает той же сессией через `--resume`. Агент работает по скиллам:
- `make-profile` — собрать профиль под игру по стандарту: спросить или найти, какие клавиши в игре, сколько оружия, поддерживает ли игра геймпад одновременно с мышью;
- `calibrate` — подобрать `real_world` замером поворота;
- `verify-profile` — прогнать TestRange (`--screenshot`) и лог ввода, убедиться, что кнопки дают нужные клавиши;
- `import-jsm` — перевести старый `.txt` в TOML.

## Этапы

1. **`crates/dualsense` + `aikm-probe`.** Полное чтение DualSense и DS4 по USB и Bluetooth (включая расширенный режим), калибровка IMU, световая полоса. Утилита печатает живое состояние.
2. **`crates/engine` + CLI `aikm`.** Профиль TOML, биндинги, гироскоп, flick stick, вывод. Проверка: TestRange без JSM ведёт себя как с пресетом `jsm/`.
3. **`app/` на Tauri.** Окно, трей, схема DualSense с подсветкой, выбор профиля, автозагрузка по exe в фокусе, HidHide-переключатель.
4. **Агент.** Миничат, скиллы, импорт старых пресетов.
5. **Полировка.** Адаптивные триггеры, вибрация, виртуальный геймпад для режима техники, установщик.

## Риски

- **Античиты** (EAC, Vanguard, BattlEye) могут игнорировать или наказывать за `SendInput`. Список таких игр держать в скилле `make-profile`.
- **Steam Input** тоже захватывает DualSense и двоит ввод. Профиль должен проверять это и подсказывать отключить Steam Input для игры.
- **Bluetooth и гибрид:** после перевода DualSense в расширенный режим игры на DirectInput / Windows.Gaming.Input не видят стики. Гибрид по Bluetooth работает только для игр на SDL или Steam Input.
- **Калибровка `real_world`** у каждой игры своя; без замера flick stick промахивается.
