# Проверка профиля в TestRange

TestRange (`demo/`) — тестовый шутер: 8 оружий парами под лицевые кнопки (клавиши 1–8), справа лог
каждого нажатия с длительностью и интервалом повтора, поворот как в Source (`real_world = 45.4545`).

Сборка, если exe нет или код менялся:

```bash
cargo build --release -p engine -p testrange
```

## 1. Статическая проверка

```bash
target/release/aikm.exe check profiles/<игра>.toml
```

Сверить напечатанное с задуманным: каждая кнопка → нужная клавиша игры, тап/удержание, слой r2 с
оружием (`1 · повтор 2` — пара), калибровка, режим движения. Ошибка парсера (неизвестная клавиша,
`next` без `press`, лишнее поле) — исправить профиль.

## 2. Скриншот игры

```bash
target/release/testrange.exe --screenshot <scratchpad>/shot.png [--overlay help|map|inv|pause] [--weapon 1-8] [--anim fire|reload|swing|throw|ads|switch] [--after 0.6]
```

Ждёт 2,5 с прогрева, снимает кадр и выходит. Открыть PNG и посмотреть. Так проверяется, что игра
запускается и как выглядит состояние (оружие, оверлей); живой ввод со скриншота не виден.
Скриншоты класть в scratchpad, не в репозиторий.

## 3. Лог ввода: что движок реально шлёт

Профиль с `exe` действует, только пока его игра в фокусе. Чтобы проверить игровой профиль в
TestRange, сделать временную обёртку (файлы на `_` автозагрузка не трогает):

```toml
# profiles/_verify.toml
extends = "<игра>"
exe = "testrange.exe"
```

Сухой прогон — в систему ничего не уходит, каждое событие печатается в stderr как
`время +Клавиша` / `время −Клавиша`:

```bash
target/release/aikm.exe run profiles/_verify.toml --dry
```

Запускать в фоне, вывод в файл в scratchpad. Попросить пользователя: открыть TestRange
(`target/release/testrange.exe`), держать геймпад секунду неподвижно (калибровка), затем по
списку нажать кнопки, которые надо проверить — тап, удержание, двойное, R2 + каждая лицевая
дважды. Потом прочитать лог и сверить: тап даёт клавишу на ~40 мс, удержание — клавишу удержания
после 150 мс, повторное R2 + □ — чётный слот. Без `--dry` (настоящий вывод) то же видно в логе
справа в самом TestRange.

Если в TestRange проверяется режим WASD, в меню TestRange (Esc) выключить «Движение стиком
геймпада», иначе демка читает стик напрямую. `[controller] hide = true` прячет геймпад только при
настоящем выводе: проверка — в TestRange «Геймпадов видит игра: 0».

После проверки удалить `profiles/_verify.toml` и остановить фоновый `aikm`.

## 4. Итог

Пользователю: что совпало, что нет (кнопка → ожидали / пришло), что исправлено в профиле.
Калибровку флика в TestRange проверять бессмысленно для другой игры — её проверяет пользователь в
самой игре фликом на 360° (см. make-profile).
