# Импорт пресета JoyShockMapper

Пресеты пользователя лежат в
`C:\Users\Anded\OneDrive\Anded_Light\SOFT\JoyShockMapper_x64_v3.3.0\GyroConfigs` — **только
читать**, ничего там не менять. Файлы `*.bak` и копии — старые версии; в подпапках (`Dusk/`,
`ULTRAKILL/`, …) лежат файлы состояния оружия, сами по себе это не пресеты.

## 1. Перевести

```bash
cargo build --release -p jsm-import
target/release/aikm-import "<путь к пресету.txt>" -o profiles/<игра>.toml --game "<Игра>" --exe <игра>.exe
```

Без `-o` профиль печатается в stdout. Сводка (кнопок, в слоях, не перенесено строк) — в stderr.
Пресет передавать по пути внутри его папки `GyroConfigs`: подключения (`GyroConfigs/_3Dmouse.txt`) и
файлы состояния ищутся относительно неё, как в JSM. Утилита сама прогоняет результат через
парсер движка: если она отработала, профиль валиден.

Что переносится:
- одиночные биндинги, тап/удержание (`+ = ESC M`), двойное нажатие (`W,W = Z`), аккорды
  (`ZR,N = 4` → `[layer.r2]`); последняя строка выигрывает, как в JSM;
- калибровка, гироскоп (в том числе из подключённого `_3Dmouse.txt`), `RIGHT_STICK_MODE = FLICK`,
  `GYRO_OFF`, мёртвые зоны, `HOLD_PRESS_TIME`, `DBL_PRESS_WINDOW`, `TRIGGER_THRESHOLD`;
- левый стик на четырёх клавишах → `mode = "wasd"`, `LRING` + `LEFT_RING_MODE` → `walk`/`sprint`;
- `TOUCHPAD_MODE = GRID_AND_STICK` с `GRID_SIZE = 2 1` или `2 2`: `T1,CAPTURE` … → `pad_left` /
  `pad_right` или четверти `pad_up_left`, `pad_up_right`, `pad_down_left`, `pad_down_right` (JSM считает ячейки построчно с верхней левой);
- файлы состояния оружия (`ZR,N = 6\ "Game/N.txt"\`) → пары `press` + `next`; если на всех четырёх
  лицевых кнопках цифры — сворачиваются в `[weapons]`;
- кнопка, которая подгружает файл с другими `LUP/LDOWN/LLEFT/LRIGHT` → `ToggleMovement`.

Что не переносится, утилита пишет в конец профиля блоком `# Не перенесено:` с причиной:
модификаторы `! ^ \ /` и турбо `+`, одновременные нажатия `L3+R3`, диагонали `UP*RIGHT`,
`LIGHT_BAR`, `VIRTUAL_CONTROLLER` и кнопки `X_*`, сетка тачпада кроме 2×1 и 2×2, `GYRO_ON`, правый стик
AIM, `STICK_SENS` и прочие настройки стика-прицела, левый стик частично на клавишах.

## 2. Довести руками

Импорт — точная копия старого пресета, а не профиль по стандарту. После него:

1. Прочитать блок «Не перенесено» и решить по каждой строке: перенести иначе (комбинация
   `L3+R3` → свободная кнопка или `[layer.r2]`), бросить (настройки стика-прицела при flick
   ничего не значат) или спросить пользователя.
2. Свести к стандарту (`docs/layout-standard.md`, скилл `make-profile`): заменить начало файла на
   `extends = "_base"` и удалить строки, совпадающие с `_base.toml`; добавить `[layer.r2]`
   `l3 = "ToggleMovement"`, если его нет; бег на L3 из пресета (`L3 = LSHIFT`) убрать — в `_base` он
   одним кликом (`latch`); гироскоп выключать касанием тачпада
   (`gyro.off = "touch"`), если пресет делал это другой кнопкой — спросить, оставить ли.
   Отклонения от стандарта, которые пользователь сознательно держал (D-pad как WASD, своя кнопка
   выключения гироскопа), не ломать без спроса — перечислить и спросить.
3. Вписать `exe`, если не дан `--exe` (см. make-profile, «Что узнать об игре»).
4. `RIGHT_STICK_MODE` не задан → импорт ставит `flick.enabled = false`; включить, если пользователь
   играет с flick stick.
5. `hide`: пресеты JSM геймпад не прятали. Если подсказки в игре мигали — `[controller] hide = true`
   при `mode = "wasd"`.

## 3. Проверить

```bash
target/release/aikm.exe check profiles/<игра>.toml
```

Затем скилл `verify-profile`. Пользователю — что перенеслось, что отброшено и почему, какие
вопросы остались.
